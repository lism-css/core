# Docs Update

`apps/site/src/content/ja/` の MDX を最新ソースと照合して修正し（フェーズ1）、修正後の `ja/` を正として `en/` へ翻訳同期する（フェーズ2）。
優先順位: パッケージソース（`packages/lism-css/`, `packages/lism-ui/`）> `ja/` > `en/`。


## 対象範囲

- `$ARGUMENTS` でファイル・ディレクトリ指定あり: その範囲のみ（`ja/` 基準。`en/` はフェーズ2で対応ファイルが同期される）
- `root`: `ja/` 直下の mdx のみ（サブディレクトリ除外）
- 未指定: `ja/` 配下の全 `.mdx`
- `_demo/` は常に除外


## 対象ファイルの分類とグルーピング

| グループ | ディレクトリ | 内容 | 照合対象 |
|---|---|---|---|
| A | `core-components/` | Lism コアコンポーネント | `lism-css` のコンポーネント・Props 定義 |
| B | `primitives/`（`l--*`, `a--*`） | CSS プリミティブ | `lism-css` の SCSS・コンポーネント |
| C | `trait-class/`（`is--*`） | トレイトクラス | `lism-css` の SCSS・コンポーネント |
| D | `property-class/` | プロパティクラス | `lism-css` の config・SCSS |
| E | `tokens/` | デザイントークン | `lism-css` の config・SCSS |
| F | `ui/` 直下 | `@lism-css/ui` コンポーネント（Blocks） | `lism-ui` のソース |
| G | `ui/examples/` | パッケージ外の部品・技法の実装例（Examples） | `lism-css` のコンポーネント |
| H | `customize/` とルート直下 | 概要・導入・カスタマイズガイド | `package.json`、ビルド設定、ソース全般 |

3件以下のグループは隣接グループと統合し、多いグループ（H 等）は分割してよい。


## フェーズ1: ja の照合修正

1. 対象ファイルを上の表で分ける
2. `lism-docs-editor` をグループ単位で並列起動する。渡すもの:
   - 担当 mdx のパス一覧
   - グループの照合対象
   - このコマンドの実行時に追加の観点を指示されていれば、それ
   チェック観点・作業ルールはエージェント定義（`.claude/agents/lism-docs-editor.md`）に集約されている。コマンド側で再掲しない
3. 各結果（修正あり/なしと修正内容）を集約する。報告はフェーズ3でまとめる


## フェーズ2: en への翻訳同期

`.claude/commands/docs-translation.md` の手順を、次の差分だけ変えて実行する。

- 対象範囲: フェーズ1と同じ
- 手順2の実行承認は行わない。分類結果を簡潔に報告し、そのまま実行する。ただし `en/` にのみあるファイルの削除だけは実行前にユーザーへ確認する（0件なら不要）
- フェーズ1で修正したファイルは、修正内容を差分の概要としてサブエージェントに渡す
- 手順4の検証（日本語残留チェック → ビルド）はそのまま行う
- 手順5の報告はフェーズ3に統合する


## フェーズ3: 報告

- フェーズ1: ja の修正ファイル一覧と修正内容の要約
- フェーズ2: en の新規/更新/削除/スキップ件数と要点。セルフチェックで直した件数
- 検証: 日本語残留の結果とビルド成否（未実施ならその理由）。失敗時はエラーの要点だけ報告し、修正せずユーザーの判断を仰ぐ

修正内容はユーザーが `git diff` で確認できる。
