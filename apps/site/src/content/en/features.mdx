## Handles the entire CSS architecture of your site

Lism CSS is not just a utility class package.

- Design token definitions
- Naming conventions for class names and variable names
- Layer (`@layer`) hierarchy definitions

These are all defined comprehensively, making Lism CSS a framework that **takes full ownership of your site's entire CSS architecture**. (As a trade-off, coexistence with other CSS frameworks is not intended.)

CSS specificity is managed through CSS Layers, organized in the following hierarchy:

```
lism-base → lism-block → lism-trait → lism-primitive → lism-custom → lism-utility
```

`lism-base` includes a `reset` sub-layer. `lism-block` holds the base styles for common site-wide parts prefixed with `b--` — placed low in the order so explicitly added classes (`is--` / `has--` / `l--`, etc.) take precedence. `lism-trait` is the layer for Trait Classes — `is--` (role declaration) and `has--` (feature attachment) — and `lism-primitive` is further divided into `layout` and `atomic` sub-layers. `lism-custom` is the layer for your own custom classes and overrides.


:::check
While there is a learning curve to understand Lism's design, projects using Lism benefit from a significantly reduced burden of "thinking about CSS architecture."
:::


## Token design that creates a natural rhythm

Lism provides carefully crafted design tokens for spacing and font size scaling.

By reusing tokens consistently, your designs will **naturally develop a smooth rhythm** without any extra effort.  
This also leads to improved maintainability and consistency.

Reference: [On typography and spacing scaling design](https://css-notes.com/layout/typography-scaling/)


## Layout-first primitive design

Common layout elements used on websites are broken down into reusable, generalized building blocks.

This is inspired by the concept of **layout primitives** from [Every Layout](https://every-layout.dev/).

- `l--flex` — Flexbox-based layout
- `l--stack` — Vertical stacking layout
- `l--columns` — Column layout
- `l--center` — Centered layout
- `l--switchColumns` — Layout that automatically switches between columns and stacked based on container width

among many other layout primitives.


## Utility design leveraging CSS variables

Like [Tailwind CSS](https://tailwindcss.com/), Lism provides utility classes corresponding to individual CSS properties.  
However, it does not generate classes for every property–breakpoint combination.

Through a **unique approach built on CSS custom properties**, you can handle responsive layouts flexibly without bloating your CSS.

For example, Lism provides basic token classes like `-p:20`, but not breakpoint-prefixed classes like `md:p-30`.  
Instead, you combine the `-p_md` class with the `--p_md` variable to achieve the same effect.

:::check
This lets you **switch values at breakpoints** for all key CSS properties while keeping the CSS size small.
:::


## A design approach that expects you to write CSS

Lism CSS takes a different approach from [Tailwind CSS](https://tailwindcss.com/), which puts everything in HTML, and from CSS-in-JS, which encapsulates styles in JSX.

- **Key layouts and light decoration** → Quickly compose with classes and CSS variables
- **Detailed styling and fine-tuning** → Carefully craft with native CSS

This balance is central to the design.  
Rather than solving everything with classes, the expectation is that you will write CSS where CSS should be written.


## Layouts independent of media queries

Inspired by [Every Layout](https://every-layout.dev/), Lism CSS includes several **layout primitives that automatically adapt to their container's width without relying on media queries**.

- `l--autoColumns` — Column count adjusts automatically based on container width
- `l--switchColumns` — Automatically switches between columns and stacked layout based on container width
- `l--withSide` — Layout automatically switches based on the main content width you want to keep


### Container queries adopted by default

Traditional breakpoint-based responsive design is also supported.  
What sets Lism apart is that **container queries are used by default** rather than media queries.

:::warning
Note that **an ancestor element must have a container definition** for responsive value switching with container queries to work correctly.
(In Lism CSS, you simply need to add the `is--container` class to an ancestor element.)
:::

Beyond that, there are a few behavioral quirks to be aware of — for example, `position: fixed` behaves differently inside a container element.
In return, components can independently switch their layout based on the width of their context, enabling highly reusable designs that work correctly no matter where they are placed.
