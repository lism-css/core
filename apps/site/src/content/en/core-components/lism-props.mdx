The props specific to Lism CSS that `<Lism>`-family components accept are called **Lism Props**.

{/* In addition to the above, there are several more complex ones. These are explained in the [Notes](#notes) section below. */}


{/* Lism Props are mainly classified into the following three types: */}

{/* |Type|Description|
|---|---|
|**Common Props**|Basic shared properties|
|**Trait Props**|Props for outputting classes classified as [Trait Class](/en/docs/trait-class/)|
|**CSS Props**|Props for outputting classes classified as [Property Class](/en/docs/property-class/)| */}

## `as`

Specifies the HTML tag or external component to render. Defaults to `div`.

<PreviewTitle>Example of specifying an HTML tag</PreviewTitle>
```jsx 'as="p"'
<Lism as="p">Lorem ipsum texts...</Lism>

↓

<p>Lorem ipsum texts...</p>
```

By passing an external component, you can have `<Lism>` **delegate rendering to that component**.

<Preview>
  <PreviewTitle>Example: rendering Lism's `<Media>` component using Next.js's `<Image>`</PreviewTitle>
  <PreviewCode>
```jsx
import Image from 'next/image';

<Media as={Image} src="..." p="20" bd />
```
  </PreviewCode>
</Preview>

Lism Props (`p` and `bd` in the example above) are processed first to produce `className` and `style`, which are then forwarded to the component specified by `as`.
This lets you apply Lism Props to non-Lism components.


## `className`

The standard prop for attaching class names to a component. Use it for `b--` / `c--` base classes (Block Class / Custom Class) or any other external styles.

:::info
The old dedicated `lismClass` / `variant` slots have been removed. BEM modifier expansion is now handled by the `buildModifierClass` helper in `@lism-css/ui` on the UI-component side.
:::

<PreviewTitle>Example</PreviewTitle>
```jsx 'className="c--myComponent"'
<Lism p="10" className="c--myComponent">Lorem ipsum texts...</Lism>

↓

<div class="c--myComponent -p:10">Lorem ipsum texts...</div>
```


## `set` / `util`

`set` specifies [Set Class](/en/docs/set-class/) entries (`set--{name}`),  
`util` specifies [Utility Class](/en/docs/utility-class/) entries (`u--{name}`).

<PreviewTitle>Example</PreviewTitle>
```jsx 'set="bxsh"' 'util="cbox"' "set--bxsh" "u--cbox"
<Lism set="bxsh" util="cbox">...</Lism>

↓

<div class="set--bxsh u--cbox">...</div>
```

### Multiple values

Both props accept space-separated values.

```jsx
<Lism set="hov" hasTransition util="cbox trim">...</Lism>
```

### Excluding with `-` prefix

Prefix a value with `-` to exclude that identifier. Use this to remove a class that has been applied internally by a component.

```jsx
{/* Exclude set="plain" (set--plain) that MyButton applies by default */}
<MyButton set="-plain">...</MyButton>

{/* Exclude u--trim and add u--cbox */}
<MyCallout util="-trim cbox">...</MyCallout>
```


## `layout` / `atomic`

`layout` and `atomic` are props for specifying Layout Primitive Classes (`l--*`) and Atomic Primitive Classes (`a--*`), respectively.


For example, specifying `layout='flow'` outputs the `l--flow` class, and specifying `atomic='divider'` outputs the `a--divider` class.

<PreviewTitle>Example</PreviewTitle>
```jsx 'layout="flow"' 'atomic="divider"' "l--flow" "a--divider"
<Lism layout="flow">Lorem ipsum texts...</Lism>
<Lism atomic="divider" />

↓

<div class="l--flow">Lorem ipsum texts...</div>
<div class="a--divider"></div>
```

:::info
Some `layout` / `atomic` values enable additional dedicated processing.

- Example 1: `layout="withSide"` accepts `sideW` / `mainW`
- Example 2: `atomic="spacer"` accepts `w` / `h` as spacing tokens
:::


## Trait Props

Props corresponding to Trait Classes (`is--*` / `has--*`).


| Prop | Output class | Purpose |
|---|---|---|
| `isWrapper(='{s\|m\|l\|xl}')` | `is--wrapper` + `-contentSize:{s\|m\|l\|xl}` | Content width restriction |
| `isLayer` | `is--layer` | Absolute positioned layer (inset:0) |
| `isBoxLink` | `is--boxLink` | Make entire box clickable |
| `isCoverLink` | `is--coverLink` | Link with a clickable area covering the parent element |
| `isContainer` | `is--container` | Container query target |
| `isSide` | `is--side` | Side element |
| `isSkipFlow` | `is--skipFlow` | Skip Flow spacing |
| `hasTransition(='{props}')` | `has--transition` + `--transitionProps:{props}` | Sets `transition` properties via CSS variables. Pass a string to specify which properties to transition |
| `hasGutter` | `has--gutter` | Reserves a unified horizontal gutter (`--gutter` / `--gutter--base`) |
| `hasSnap` | `has--snap` | Sets `scroll-snap-*` properties via CSS variables |
| `hasMask` | `has--mask` | Sets `mask` property via CSS variables |

## CSS Props

Props corresponding to [Property Class](/en/docs/property-class/) (`-{prop}:{value}`).

Use the same shortened CSS property names as the `{prop}` part (e.g., `font-size` → `fz`, `padding` → `p`).


<Spacer h="10"/>

The output format is determined by the value specified via `prop={value}`:

| Value | Output format | Example |
|------|------|-----|
| Token / preset value | `-{prop}:{value}` class | `fz='l'` → `-fz:l` |
| `true` | `-{prop}` class only (no variable) | `bd` → `-bd` |
| Value starting with `:` | Forced utility class | `p=':hoge'` → `-p:hoge` |
| Other values (BP-supported) | `-{prop}` class + `--{prop}` variable | `fz='20px'` → `-fz` + `--fz:20px` |
| Other values (BP-unsupported) | Direct `style` attribute output | `o='0.7'` → `opacity:0.7` |
| Other values (variable-only) | `--{prop}` variable only | `bdw='2px'` → `--bdw:2px` |

:::note[Notes]
- **BP-supported properties**: Properties that can switch values at breakpoints. See the **BP** column in [Property Class](/en/docs/property-class).
- **Variable-only properties**: Properties such as `bds`, `bdc`, `bdw`, and `keycolor` that output only CSS variables (`--{prop}`) for values that aren't registered as classes.
- When a matching token exists but has no dedicated class, the value is output as a CSS variable. (e.g., `c='red'` → `class="-c"` + `style="--c:var(--red)"`)
:::

### Class output with `:`

Even if no corresponding Property Class exists, prefixing a value with `:` will output the string after it as a class name.

```jsx
<Lism p=":hoge">...</Lism>
// → <div class="-p:hoge">...</div>
```

Define the class in your CSS and use it wherever needed.

```css
.-p\:hoge {
  /* ... your styles ... */
}
```

:::info
Using `className='-p:hoge'` also works, but passing it as a CSS Prop via `:` ensures consistent output ordering.
:::

<Spacer h="10"/>

#### Passing `:` on its own

If you pass just `:` without any string after it, only the `-{prop}` class is output, exactly as if you had passed `true`.

```jsx
<Lism bd=":">...</Lism>
// → <div class="-bd">...</div>
```

This is handy when you want to enable a prop like `bd` (one that can be toggled on with `true`) from a path that cannot pass a boolean, such as text input.


<div id="color-mix"></div>
### Color transparency and mixing

Color props such as `c`, `bgc`, and `bdc` accept `:`-separated values to set transparency or mix two colors. The value is converted into `color-mix()` and output as a CSS variable.

| Syntax | Output | Meaning |
| --- | --- | --- |
| `{color}:{alpha}%` | `color-mix(in srgb, var(--{color}) {alpha}%, transparent)` | `{color}` at `{alpha}%` opacity |
| `{color1}:{color2}:{ratio}%` | `color-mix(in srgb, var(--{color1}), var(--{color2}) {ratio}%)` | Mix `{ratio}%` of `{color2}` into `{color1}` |

<Preview>
<PreviewTitle>Transparency</PreviewTitle>
<PreviewCode>
```jsx
<Lism bgc="black:50%">...</Lism>
// → <div class="-bgc" style="--bgc:color-mix(in srgb, var(--black) 50%, transparent)">...</div>
```
</PreviewCode>
</Preview>

<Preview>
<PreviewTitle>Mixing two colors</PreviewTitle>
<PreviewCode>
```jsx
<Lism c="text:blue:5%">...</Lism>
// → <div class="-c" style="--c:color-mix(in srgb, var(--text), var(--blue) 5%)">...</div>
```
</PreviewCode>
</Preview>

:::note[Notes]
- Values that are not tokens are passed to `color-mix()` as-is. (e.g., `bgc="currentColor:10%"` → `color-mix(in srgb, currentColor 10%, transparent)`)
- This conversion is specific to Lism Props. To get the same result with Property Classes (HTML), write the value directly, such as `style="--bgc: color-mix(in srgb, var(--black) 50%, transparent)"`.
:::


### Responsive syntax

BP-supported properties can specify values per breakpoint (`sm`, `md`, `lg`) using arrays or objects.


<Preview>
  <PreviewTitle>Example 1: array syntax (base → sm → md)</PreviewTitle>
  <PreviewCode label="JSX" slot="tab">
    ```jsx
    <Lism p={['20', '30', '5rem']}>...</Lism>
    ```
  </PreviewCode>
  <PreviewCode label="Output HTML" slot="tab">
    ```html
    <div class="-p:20 -p_sm -p_md" style="--p_sm:var(--s30);--p_md:5rem">
      ...
    </div>
    ```
  </PreviewCode>
</Preview>

<Preview>
  <PreviewTitle>Example 2: skip intermediate breakpoints (`@md` only)</PreviewTitle>
  <PreviewCode label="JSX" slot="tab">
    ```jsx
    <Lism p={[null, null, '40']}>...</Lism>
    ```
  </PreviewCode>
  <PreviewCode label="Output HTML" slot="tab">
    ```html
    <div class="-p_md" style="--p_md:var(--s40)">
      ...
    </div>
    ```
  </PreviewCode>
</Preview>

:::warning
Whether a value actually changes at a breakpoint depends on whether that property supports responsive behavior.
Check the **BP** (<small>short for breakpoint</small>) column in [Property Class](/en/docs/property-class) to see which properties are supported.
:::

For properties that do not support responsive behavior by default (i.e., no CSS is provided), you can add support via [SCSS customization](/en/docs/customize/scss/).


## `exProps`

Pass an object containing **any props you want to bypass Lism Props processing for**.

Use this when a prop name of the external component specified via `as` conflicts with a Lism Prop name and you need to explicitly mark it as belonging to the external component.

<Preview>
  <PreviewTitle>Example</PreviewTitle>
  <PreviewCode>
```jsx
<Icon as={Hoge} exProps={{ size: '1em' }} p="10" fz="l">
  ...
</Icon>
```
  </PreviewCode>
</Preview>

This way, the Lism `Icon` component processes `p` and `fz`, while the external component `Hoge` reliably receives `size`.
(In this example, `exProps` is not strictly required since Lism does not currently process `size`, but explicitly marking external component props prevents future conflicts.)


## Class output order

The `class` attribute generated by `<Lism>` is output in the following order:

```
[className (including b-- / c--)] [a--] [l--] [set--] [is-- / has--] [u--] [-]
```

| # | Prop | Example |
|---|---|---|
| 1 | User-defined class (`className` / `class`) | `b--btn`, `c--box`, `c--siteHeader` |
| 2 | `atomic` | `a--icon`, `a--divider` |
| 3 | `layout` | `l--flex`, `l--columns` |
| 4 | `set` | `set--hov` |
| 5 | `isXxxx` / `hasXxxx` (Trait) | `is--wrapper`, `is--layer`, `has--transition` |
| 6 | `util` | `u--cbox`, `u--trim` |
| 7 | `prop={value}` | `-p:20`, `-bgc:base-2`, `-hov:-c` |


:::note
The `-flow:{size}` class produced by `layout="flow"` is treated as a layout-primitive-specific configuration class, so it is emitted alongside the primitive group right after `l--flow`.
:::

:::note
The `b--*` / `c--*` classes can be placed anywhere inside `className`, but we recommend writing them at the front for readability.
:::

:::note
The order within the `class` attribute does not affect the CSS cascade (specificity or source order). This ordering is purely for readability and consistency.
:::
